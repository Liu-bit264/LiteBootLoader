# VOFA+ 可行性与定位说明（vofa_plus）

> 版本 0.1.0 · 2026-09-25 · 状态：阶段 0 交付
> 关联：[protocol.md](protocol.md) §9.2（RawData 帧模板） · AGENTS.md §9.4

## 1. 定位声明（防混淆）

**VOFA+ 不是本项目的正式升级工具**。正式升级工具为 `tools/python/bl_upgrade.py`（阶段 3，pyserial 实现）。VOFA+ 的角色严格限定为：

1. **日志观察**：USART1（115200 8N1）文本流查看 BL 运行日志；
2. **RawData 手动发帧**：十六进制手工发送协议帧，用于调试与联调演示。

## 2. 可行性分析

| 能力 | 可行性 | 说明 |
|---|---|---|
| 查看日志 | 可行 | 升级通道与日志共用 USART1；协议非活跃期日志可见（design.md ADR-009：收到 SOF 即静音，超 10 s 无帧恢复）。VOFA+ 按文本流显示即可 |
| RawData 发送 hex 帧 | 可行 | VOFA+ 的 RawData/命令通道支持十六进制输入；可直接粘贴 protocol.md §9.2 的实测帧（PING/GET_INFO/RESET 请求） |
| 接收解析帧响应 | 部分可行 | 响应帧为二进制，RawData 窗口以 hex 显示可人工比对，无自动校验 |
| 完成整流程升级 | **不采用** | 需要分帧、CRC 计算、进度与重试编排——这正是 bl_upgrade.py 的职责；VOFA+ 手工操作易出错且不可重复 |
| FireWater/JustFloat 波形协议 | 不适用 | 本项目日志为文本行，非浮点帧流；不启用 VOFA+ 波形协议 |

## 3. 配置要点（阶段 3 随工具交付配置文件）

- 串口：`COMx`，115200，8N1，无流控；
- 发送：RawData 通道，hex 模式，逐帧粘贴发送（帧间无需间隔控制，BL 帧内 50 ms 超时会丢弃不完整帧后重新同步）；
- 接收：RawData 通道 hex 显示 + 文本窗口双开（日志与响应并存）；
- 注意：改过 SEQ/CMD 的帧必须重算 CRC（protocol.md §4.1 参考实现），否则被静默丢弃。

## 4. 与正式工具的边界

| 场景 | 用 VOFA+ | 用 bl_upgrade.py |
|---|---|---|
| 看 BL 启动横幅/状态日志 | ✔ | —（工具只关心响应帧） |
| 手动验证单条命令 | ✔ | — |
| 完整镜像升级 | ✘（易错、不可重复） | ✔ |
| 升级中断恢复测试 | ✘ | ✔（阶段 3 测试项） |

阶段 3 交付物：`tools/vofa+/` 下提供 `.vofa` 配置文件与常用帧速查表；[protocol.md](protocol.md) §9.2 的帧模板保持同步。
